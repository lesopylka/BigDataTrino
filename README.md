## Данные и модель

В [data](data) находятся 10 CSV по 1000 строк. Переносы строк внутри описаний товаров обрабатываются CSV-парсером.

Одна строка исходного файла считается одной продажей. Номер `id` повторяется между файлами. Ключ продажи состоит из имени файла и номера строки `id`. Поля `sale_customer_id`, `sale_seller_id` и `sale_product_id` не используются как уникальные ключи справочников.

Сумма продажи берется из `sale_total_price`. Она не заменяется произведением цены на количество, так как эти значения в учебных данных расходятся.

Контрольные значения находятся в [expected.json](expected.json).

| Показатель | Значение |
|---|---:|
| Продажи | 10000 |
| Количество товара | 54623 |
| Сумма продаж | 2529852.12 |

В звезде используются измерения покупателей, продавцов, товаров, магазинов, поставщиков и дат. В факте хранятся ключи измерений, количество и сумма продажи.

Ключ измерения строится по полному набору его атрибутов. Так разные версии характеристик не перезаписывают друг друга. Это учебная модель версий, без восстановления истории реальных изменений.

## Витрины

Каждая витрина содержит несколько показателей. Поле `metric` определяет показатель, `entity` определяет объект, `period` содержит период, `value` содержит значение. В ClickHouse это шесть отдельных таблиц. В NiFi это шесть SQL-представлений PostgreSQL.

| Витрина | Показатели |
|---|---|
| products | Топ-10 по количеству, выручка категорий, средний рейтинг, число отзывов |
| customers | Топ-10 по сумме покупок, уникальные email по странам, средний чек |
| time | Выручка по месяцам и годам, разница с предыдущим периодом, средний чек по месяцам |
| stores | Топ-5 по выручке, выручка городов и стран, средний чек |
| suppliers | Топ-5 по выручке, средняя наблюдаемая цена, выручка по странам |
| quality | Лучшие и худшие рейтинги, больше всего отзывов, корреляция рейтинга и количества |

Товары в сводных отчетах группируются по названию. Уникальные версии товара предварительно выделяются по всем характеристикам. Рейтинг усредняется по версиям, отзывы суммируются по версиям, а не по повторным продажам той же версии. Поле отзывов трактуется как число отзывов в каждой версии учебного товара.

Клиенты группируются по email, магазины по `store_name`, поставщики по `supplier_name`. Разные строки с одним названием входят в одну группу, даже если email различается. Средний чек считается по строкам продаж, так как отдельного номера заказа в CSV нет. Корреляция считается по товарам между средним рейтингом и суммарным проданным количеством. При отсутствии предыдущего периода изменение выручки равно NULL.

## Реализация

[Scripts/load.py](Scripts/load.py) читает CSV в числовом порядке имен. Первые пять файлов, `MOCK_DATA.csv` и номера 1-4, попадают в ClickHouse. Номера 5-9 попадают в PostgreSQL. В каждой базе должно быть по 5000 строк.

[sql/02_star.sql](sql/02_star.sql) объединяет источники через Trino с помощью `UNION ALL`, сохраняет staging, измерения и факты в ClickHouse. [sql/reports](sql/reports) содержит шесть расчетов из звезды. Выполнение запросов и проверка количества и сумм находятся в [Scripts/trino.py](Scripts/trino.py).

`clickhouse.map-string-as-varchar=true` приводит `String` ClickHouse к `varchar` Trino. Поля обоих источников совместимы при `UNION ALL`. После изменения каталога нужно перезапустить Trino.

Коннекторы описаны в [trino/catalog](trino/catalog), таблицы источников в [sql/01_start.sql](sql/01_start.sql) и [sql/clickhouse.sql](sql/clickhouse.sql).

## Запуск

Нужны Docker с Compose v2, интернет для загрузки образов и минимум 6 ГБ свободной памяти.

```bash
docker compose up -d --build
docker compose logs -f load etl
```

Контейнер `etl` должен завершиться с кодом 0. Trino доступен на `http://localhost:8080`, PostgreSQL на `localhost:5436`, ClickHouse на `http://localhost:8124`. Данные PostgreSQL `postgres/postgres`, база `postgres`. Данные ClickHouse `lab/lab`, база `lab`.

```bash
docker compose exec trino trino --execute "SELECT count(*) FROM clickhouse.lab.fact_sales"
docker compose exec trino trino --execute "SELECT * FROM clickhouse.lab.report_products"
```

Повторный расчет выполняется последовательно. Таблицы модели и витрин пересоздаются, чтение во время расчета может видеть промежуточное состояние.

```bash
docker compose run --rm load
docker compose run --rm etl
```

## Проверки и ограничения

Проверены количество строк в каждом CSV, уникальность составного ключа и контрольные суммы. Для SQL витрин выполнен локальный расчет на полном наборе данных. Контейнерный запуск и связь всех сервисов требуют проверки команд выше. Успешный локальный SQL-расчет не заменяет интеграционный запуск.

Параметры баз в compose предназначены для локальной лабораторной работы. Сервисы привязаны к localhost. Разные работы можно запускать по отдельности. Инициализационные SQL выполняются только на пустом томе PostgreSQL.

Остановить сервисы с сохранением данных можно командой `docker compose down`. Команда `docker compose down -v` удаляет учебные базы, очереди и состояние сервисов. Для запуска с нуля после удаления томов повторить шаги из раздела запуска.

## Проверка после обновления

Изменение каталога применяется после перезапуска Trino. Затем нужно заново построить модель и отчеты.

```bash
docker compose restart trino
docker compose run --build --rm etl
```

В конце ETL [Scripts/check_reports.py](Scripts/check_reports.py) сравнивает топы, средние и временные показатели с независимым расчетом по CSV. Магазины и поставщики сравниваются по названиям.
